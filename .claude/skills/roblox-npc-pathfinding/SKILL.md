# Roblox NPC Pathfinding

## 1. Skill Architecture

This skill generates a 3-layer NPC pathfinding system:

| Layer | Module | Role |
|-------|--------|------|
| **Movement** | `NPCPathfinder` (`assets/npc-pathfinder.luau`) | Movement primitives: `moveTo`, `followTarget`, `patrol`, `stop`, `hasLineOfSight`. Handles path computation, waypoint traversal, stuck detection, collision groups, humanoid optimization. |
| **State Machine** | `NPCStateMachine` (`assets/npc-state-machine.luau`) | Generic FSM ticked externally via `PostSimulation`. States have `onEnter`/`onUpdate`/`onExit` hooks. Decoupled from NPC-specific logic. |
| **Behavior States** | Generated per NPC type | Per-NPC-type state definitions. Generated by the wizard, customized per user answers. Each is a `StateMap` table consumed by `NPCStateMachine`. |

**Optional supporting modules:**

| Module | Role |
|--------|------|
| `BehaviorHelpers` (`assets/behavior-helpers.luau`) | Shared utilities: `findNearestPlayer`, `detectNearestPlayerInRange`, `getRandomPointInRadius`, `evaluateChaseTarget`, `createWaypointMarkers`, `clearCache` |
| `NPCManager` (documented pattern, not an asset) | Centralized spawning, state machine wiring, tick loop, lifecycle cleanup. Too project-specific to ship as a generic asset. |

**Data flow:** NPCManager spawns models, creates pathfinders, creates state machines with behavior state maps, and runs a single `PostSimulation` tick loop. Each tick calls `stateMachine:update(dt)`. State hooks call pathfinder methods (`followTarget`, `patrol`, `moveTo`, `stop`) to drive movement.

## 3. Interactive Wizard Flow

### Question 1 -- NPC Type

> What behavior should this NPC have?
> - **Chase** -- Pursues nearest player when detected (enemies, zombies, hostile mobs)
> - **Patrol** -- Follows a fixed waypoint route (guards, townspeople, ambient creatures)
> - **Wander** -- Roams randomly within an area (wildlife, idle NPCs)
> - **Guard** -- Patrols a zone, chases intruders, returns to post (sentries, boss adds)
> - **Custom** -- Describe the behavior you want

### Question 2 -- Type-Specific Follow-Ups

**For Chase:**
- Detection radius? (default: 30 studs)
- Walk speed? (default: 16)
- What happens at arrival? (stop, attack callback, orbit target)
- Should walls block detection? (`REQUIRE_LOS = true` recommended, default: true)
- Should it give up if target hides behind a wall? (`LOS_MEMORY` seconds, default: 3; nil = chase forever once spotted)
- Should it give up if target escapes detection range? (distance threshold or never)

**For Patrol:**
- How many waypoints? (provide Vector3 positions or describe layout)
- Loop mode? (`loop` = A->B->C->A, `pingpong` = A->B->C->B->A)
- Wait time at each waypoint? (default: 2 seconds)
- Should patrol be interruptible? (e.g., detect player -> chase)

**For Wander:**
- Center position and radius? (default: spawn position, 25 studs)
- Pause between wanders? (min/max seconds, defaults: 1-3)
- Are there obstacles in the wander zone? (enables obstacle rejection raycast)

**For Guard:**
- Detection method? (distance + LOS recommended, distance-only simpler)
- Detection radius? (default: 25 studs)
- Should walls block detection? (`REQUIRE_LOS = true` recommended, default: true)
- How long should it chase after losing sight? (`LOS_MEMORY` seconds, default: 5; nil = chase forever)
- Waypoints or random patrol within radius?
- How far will it chase before returning to post?
- Walk speed? (default: 12)

**For Custom:**
- What states does this NPC have? (list them)
- What triggers transitions between states?
- Does it need player detection? LOS checks? Target tracking?

### Question 3 -- Project Context

- Where do server modules live? (ServerScriptService, ServerStorage, or describe structure)
- Do you already have `NPCPathfinder` and `NPCStateMachine` modules? (skip asset placement if yes)
- How many concurrent NPCs of this type? (affects performance guidance)
- Is the environment static or dynamic? (moving obstacles need different handling)

## 4. Critical Prerequisites (ALL Scenarios)

### 1. Enable Improved Pathfinding Algorithm

In Roblox Studio: Workspace -> Properties -> `PathfindingUseImprovedSearch` -> **Enabled**

This fixes zig-zagging, wall-hugging, agent size being ignored, and terrain navmesh issues. There is no reason to leave this off.

**This property is NOT scriptable.** You cannot enable it via code or MCP -- it must be set manually in Studio.

### 2. NPC Model Requirements

Every pathfinding NPC needs:
- A `Model` with `PrimaryPart` set to `HumanoidRootPart`
- A `Humanoid` instance (for `MoveTo` and `MoveToFinished`)
- `HumanoidRootPart` must be unanchored
- Model must be in `Workspace` when pathfinding

### 3. Network Ownership

Lock network ownership to the server immediately on spawn:

```lua
npcModel.PrimaryPart:SetNetworkOwner(nil)
```

Without this, `Humanoid:MoveTo()` and `MoveToFinished` have unpredictable latency as ownership bounces between server and nearest client. This is the #1 cause of jittery NPC movement.

The NPCPathfinder module handles this automatically in its constructor.

### 4. NPC Collision Group

When multiple NPCs converge, their HumanoidRootParts collide and cause physics jitter. Fix by putting all NPCs in a collision group with self-collisions disabled:

```lua
local PhysicsService = game:GetService("PhysicsService")
PhysicsService:RegisterCollisionGroup("NPCs")
PhysicsService:CollisionGroupSetCollidable("NPCs", "NPCs", false)
-- Then assign NPC parts: part.CollisionGroup = "NPCs"
```

The NPCPathfinder module handles this automatically via the `CollisionGroup` config option.

### 5. Script Placement

- Pathfinding logic runs on the **server** (ServerScriptService or ServerStorage)
- Do NOT place NPC AI modules in ReplicatedStorage -- exploiters can decompile client-visible code and learn behavior patterns
- A centralized ModuleScript is preferred over script-per-NPC

## 5. Behavior State Templates

Each template shows the state map structure. When generating code, substitute config values from the wizard answers.

### Template: Chase (Idle <-> Chasing)

Two states. Idle scans for players. Chasing follows with `followTarget`.

```lua
--!strict
-- ChaseStates.luau - Generated behavior states for Chase NPC
-- States: Idle (scanning) <-> Chasing (pursuing target)

local NPCStateMachine = require(path.to.NPCStateMachine)
local BehaviorHelpers = require(path.to.BehaviorHelpers)
local GameConfig = require(path.to.GameConfig)

-- WIZARD VALUES: substitute from user answers (or read from GameConfig)
local CONFIG = {
    DETECTION_RADIUS = 30,        -- studs
    RECOMPUTE_INTERVAL = 0.5,     -- seconds
    ARRIVAL_DISTANCE = 5,         -- studs
    REEVALUATE_INTERVAL = 3,      -- seconds between target re-evaluation
    REQUIRE_LOS = true,           -- walls block detection (set false for omniscient)
    LOS_MEMORY = 3,               -- seconds to chase after losing sight (nil = chase forever)
}

local ChaseStates: NPCStateMachine.StateMap = {
    Idle = {
        onEnter = function(ctx: any)
            ctx.pathfinder:stop()
        end,

        onUpdate = function(ctx: any, _dt: number): string?
            return BehaviorHelpers.detectNearestPlayerInRange(ctx, CONFIG, "chaseTarget", "Chasing")
        end,
    },

    Chasing = {
        onEnter = function(ctx: any)
            local target = ctx.chaseTarget
            if not target then
                return
            end

            ctx.pathfinder:followTarget(target, {
                recomputeInterval = CONFIG.RECOMPUTE_INTERVAL,
                arrivalDistance = CONFIG.ARRIVAL_DISTANCE,
                -- onArrival = function(target) end,  -- WIZARD: attack callback here
                -- onTargetLost = function() end,     -- WIZARD: optional lost callback
            })
        end,

        onUpdate = function(ctx: any, dt: number): string?
            -- Throttle re-evaluation (don't check every frame)
            ctx.chaseReevalTimer = (ctx.chaseReevalTimer or 0) + dt
            if ctx.chaseReevalTimer < CONFIG.REEVALUATE_INTERVAL then
                return nil
            end
            ctx.chaseReevalTimer = 0

            return BehaviorHelpers.evaluateChaseTarget(ctx, CONFIG, "chaseTarget", "Idle", false)
        end,

        onExit = function(ctx: any)
            ctx.pathfinder:stop()
            ctx.chaseReevalTimer = nil
            ctx.losLostTimer = nil
        end,
    },
}

return ChaseStates
```

**Key patterns:**
- `detectNearestPlayerInRange` handles distance + optional LOS check in one call — replaces inline detection boilerplate
- `REQUIRE_LOS = true` blocks detection through walls; `LOS_MEMORY` adds a countdown timer when LOS is lost during chase
- `evaluateChaseTarget` handles: current target still valid? LOS still held (if `LOS_MEMORY` configured)? Closer player available? Returns "Idle" if target lost or LOS memory expires, "Chasing" for target switch, nil to stay
- `followTarget` uses event-driven waypoint advancement via `MoveToFinished:Connect()` -- never a blocking compute-traverse-wait loop
- Timer-based re-evaluation (`REEVALUATE_INTERVAL`) avoids per-frame cost
- Always stop pathfinder and clear `losLostTimer` in `onExit`

### Template: Patrol (Patrolling)

Single state. Calls `pathfinder:patrol()` with waypoints.

```lua
--!strict
-- PatrolStates.luau - Generated behavior states for Patrol NPC
-- States: Patrolling (loops waypoints in sequence)

local NPCStateMachine = require(path.to.NPCStateMachine)
local BehaviorHelpers = require(path.to.BehaviorHelpers)

-- WIZARD VALUES: substitute from user answers
local WAYPOINTS = {
    Vector3.new(-30, 5, -20),
    Vector3.new(-50, 5, -20),
    Vector3.new(-50, 5, 20),
    Vector3.new(-30, 5, 20),
}
local LOOP_MODE = "loop"   -- "loop" or "pingpong"
local WAIT_TIME = 2        -- seconds at each waypoint

local PatrolStates: NPCStateMachine.StateMap = {
    Patrolling = {
        onEnter = function(ctx: any)
            -- Optional: debug waypoint markers
            -- ctx.debugFolder = BehaviorHelpers.createWaypointMarkers(WAYPOINTS, Color3.fromRGB(250, 204, 21), true)

            ctx.pathfinder:patrol(WAYPOINTS, {
                loopMode = LOOP_MODE,
                waitTime = WAIT_TIME,
                onWaypoint = function(index: number)
                    -- Called when NPC reaches each waypoint
                end,
            })
        end,

        onExit = function(ctx: any)
            ctx.pathfinder:stop()
        end,
    },
}

return PatrolStates
```

**Key patterns:**
- `patrol()` handles loop/pingpong internally -- no manual index management needed
- `onWaypoint` callback fires at each arrival (use for animations, sounds, etc.)
- Optional `BehaviorHelpers.createWaypointMarkers()` for debug visualization
- Stop pathfinder in `onExit` to prevent orphaned patrol thread

### Template: Wander (Wandering)

Single state. Spawns a thread that loops: pick random point -> moveTo -> pause.

```lua
--!strict
-- WanderStates.luau - Generated behavior states for Wander NPC
-- States: Wandering (roams randomly within radius)

local NPCStateMachine = require(path.to.NPCStateMachine)
local BehaviorHelpers = require(path.to.BehaviorHelpers)

-- WIZARD VALUES: substitute from user answers
local CENTER = Vector3.new(0, 5, -30)
local RADIUS = 25        -- studs
local PAUSE_MIN = 1      -- seconds
local PAUSE_MAX = 3      -- seconds

local WanderStates: NPCStateMachine.StateMap = {
    Wandering = {
        onEnter = function(ctx: any)
            ctx.wanderThread = task.spawn(function()
                while ctx.model and ctx.model:IsDescendantOf(game) do
                    local target = BehaviorHelpers.getRandomPointInRadius(CENTER, RADIUS)
                    ctx.pathfinder:moveTo(target)
                    local pause = PAUSE_MIN + math.random() * (PAUSE_MAX - PAUSE_MIN)
                    task.wait(pause)
                end
            end)
        end,

        onExit = function(ctx: any)
            if ctx.wanderThread then
                task.cancel(ctx.wanderThread)
                ctx.wanderThread = nil
            end
            ctx.pathfinder:stop()
        end,
    },
}

return WanderStates
```

**Key patterns:**
- Thread spawned in `onEnter`, cancelled in `onExit`
- `getRandomPointInRadius` uses downward raycast to reject points inside obstacle geometry
- After `task.wait()`, the `while` condition verifies model still exists before continuing
- Always cancel thread AND stop pathfinder in `onExit`

### Template: Guard (Guarding <-> Chasing <-> Returning)

Most complex -- 3 states with LOS-based detection.

```lua
--!strict
-- GuardStates.luau - Generated behavior states for Guard NPC
-- States: Guarding (random patrol) <-> Chasing (pursuit) <-> Returning (back to post)

local NPCStateMachine = require(path.to.NPCStateMachine)
local BehaviorHelpers = require(path.to.BehaviorHelpers)
local GameConfig = require(path.to.GameConfig)

-- WIZARD VALUES: substitute from user answers (or read from GameConfig)
local CONFIG = {
    DETECTION_RADIUS = 25,        -- studs
    RECOMPUTE_INTERVAL = 0.5,
    ARRIVAL_DISTANCE = 5,
    REEVALUATE_INTERVAL = 1,
    DETECT_INTERVAL = 0.2,        -- seconds between detection raycasts
    PATROL_PAUSE = 1.5,           -- seconds between random waypoints
    RETURN_DWELL = 0.8,           -- minimum seconds in Returning before transitioning
    REQUIRE_LOS = true,           -- walls block detection (set false for omniscient)
    LOS_MEMORY = 5,               -- seconds to chase after losing sight (nil = chase forever)
    WAYPOINTS = {
        Vector3.new(10, 5, 25),
        Vector3.new(15, 5, 45),
        Vector3.new(0, 5, 50),
        Vector3.new(-15, 5, 45),
        Vector3.new(-10, 5, 25),
    },
}

local GuardStates: NPCStateMachine.StateMap = {
    Guarding = {
        onEnter = function(ctx: any)
            local lastIndex = ctx.guardLastWaypointIndex or 0

            ctx.guardPatrolThread = task.spawn(function()
                while ctx.model and ctx.model:IsDescendantOf(game) do
                    -- Pick random waypoint, excluding the last one visited
                    local candidates = {}
                    for i = 1, #CONFIG.WAYPOINTS do
                        if i ~= lastIndex then
                            table.insert(candidates, i)
                        end
                    end
                    local nextIndex = candidates[math.random(1, #candidates)]
                    lastIndex = nextIndex
                    ctx.guardLastWaypointIndex = nextIndex

                    ctx.pathfinder:moveTo(CONFIG.WAYPOINTS[nextIndex])
                    task.wait(CONFIG.PATROL_PAUSE)
                end
            end)
        end,

        onUpdate = function(ctx: any, dt: number): string?
            -- Throttle detection raycasts
            ctx.guardDetectTimer = (ctx.guardDetectTimer or 0) + dt
            if ctx.guardDetectTimer < CONFIG.DETECT_INTERVAL then
                return nil
            end
            ctx.guardDetectTimer = 0

            return BehaviorHelpers.detectNearestPlayerInRange(ctx, CONFIG, "guardTarget", "Chasing")
        end,

        onExit = function(ctx: any)
            if ctx.guardPatrolThread then
                task.cancel(ctx.guardPatrolThread)
                ctx.guardPatrolThread = nil
            end
            ctx.guardDetectTimer = nil
            ctx.pathfinder:stop()
        end,
    },

    Chasing = {
        onEnter = function(ctx: any)
            local target = ctx.guardTarget
            if not target then
                return
            end

            ctx.pathfinder:followTarget(target, {
                recomputeInterval = CONFIG.RECOMPUTE_INTERVAL,
                arrivalDistance = CONFIG.ARRIVAL_DISTANCE,
            })
        end,

        onUpdate = function(ctx: any, dt: number): string?
            ctx.guardReevalTimer = (ctx.guardReevalTimer or 0) + dt
            if ctx.guardReevalTimer < CONFIG.REEVALUATE_INTERVAL then
                return nil
            end
            ctx.guardReevalTimer = 0

            return BehaviorHelpers.evaluateChaseTarget(ctx, CONFIG, "guardTarget", "Returning", true)
        end,

        onExit = function(ctx: any)
            ctx.pathfinder:stop()
            ctx.guardReevalTimer = nil
            ctx.losLostTimer = nil
        end,
    },

    Returning = {
        onEnter = function(ctx: any)
            ctx.guardReachedWaypoint = false

            local rootPart = ctx.model.PrimaryPart
            if not rootPart then
                ctx.guardReachedWaypoint = true
                return
            end

            -- Find nearest waypoint to return to
            local nearestIndex = 1
            local nearestDist = math.huge
            for i, wp in CONFIG.WAYPOINTS do
                local dist = (wp - rootPart.Position).Magnitude
                if dist < nearestDist then
                    nearestDist = dist
                    nearestIndex = i
                end
            end

            ctx.guardLastWaypointIndex = nearestIndex

            ctx.guardPatrolThread = task.spawn(function()
                ctx.pathfinder:moveTo(CONFIG.WAYPOINTS[nearestIndex])
                ctx.guardReachedWaypoint = true
            end)
        end,

        onUpdate = function(ctx: any, dt: number): string?
            if ctx.guardReachedWaypoint then
                -- Minimum dwell time before transitioning back to Guarding
                ctx.guardReturnDwell = (ctx.guardReturnDwell or 0) + dt
                if ctx.guardReturnDwell >= CONFIG.RETURN_DWELL then
                    return "Guarding"
                end
                return nil
            end

            -- Can detect and chase players during return
            ctx.guardDetectTimer = (ctx.guardDetectTimer or 0) + dt
            if ctx.guardDetectTimer < CONFIG.DETECT_INTERVAL then
                return nil
            end
            ctx.guardDetectTimer = 0

            return BehaviorHelpers.detectNearestPlayerInRange(ctx, CONFIG, "guardTarget", "Chasing")
        end,

        onExit = function(ctx: any)
            if ctx.guardPatrolThread then
                task.cancel(ctx.guardPatrolThread)
                ctx.guardPatrolThread = nil
            end
            ctx.guardDetectTimer = nil
            ctx.guardReachedWaypoint = nil
            ctx.guardReturnDwell = nil
            ctx.pathfinder:stop()
        end,
    },
}

return GuardStates
```

**Key patterns:**
- `detectNearestPlayerInRange` replaces the local `detectPlayerWithLOS` helper — shared utility handles distance + optional LOS check
- `REQUIRE_LOS = true` blocks detection through walls; `LOS_MEMORY` adds a countdown timer when LOS is lost during chase — NPC gives up after N seconds without regaining sight
- `evaluateChaseTarget` with `LOS_MEMORY` config handles the full stealth loop: detect → pursue → lose sight → countdown → disengage
- Random waypoint patrol skips the last visited index to avoid back-and-forth
- Returning finds the nearest waypoint, not always the same one
- `RETURN_DWELL` minimum time makes the "Returning" state observable in debug tools
- Can interrupt return to chase if a player is detected
- Always clear `losLostTimer` in Chasing `onExit`

### Template: Custom

General pattern for any behavior:

```lua
--!strict
-- CustomStates.luau - Custom behavior state definitions
-- States: [list states and transitions here]

local NPCStateMachine = require(path.to.NPCStateMachine)

local CustomStates: NPCStateMachine.StateMap = {
    -- State names are strings. Return a state name from onUpdate to transition.
    StateName = {
        -- Called once when entering this state
        onEnter = function(ctx: any)
            -- ctx is a shared mutable table. Store behavior-specific fields here.
            -- Start pathfinder movement, spawn threads, etc.
        end,

        -- Called every tick (PostSimulation). Return state name to transition, nil to stay.
        -- Only one transition per tick (state machine enforces this).
        onUpdate = function(ctx: any, dt: number): string?
            -- Check conditions, return "NextState" to transition
            return nil
        end,

        -- Called once when leaving this state
        onExit = function(ctx: any)
            -- ALWAYS: cancel threads, stop pathfinder, clean up visuals
            -- Failure to stop pathfinder here causes orphaned movement
            ctx.pathfinder:stop()
        end,
    },
}

return CustomStates
```

## 6. NPCManager Pattern

The NPCManager is too project-specific to ship as a generic asset. Instead, here is the pattern to follow. Adapt naming, spawning, and config to fit the user's project.

**Key elements:**

```lua
-- 1. NPCEntry type: shared context table passed to state machines
type NPCEntry = {
    model: Model,
    pathfinder: typeof(NPCPathfinder.new(nil :: any)),
    stateMachine: typeof(NPCStateMachine.new("" :: any, {} :: any, {} :: any)),
    behaviorType: string,
    -- ...behavior-specific fields populated by state hooks (chaseTarget, wanderThread, etc.)
}

-- 2. Storage for active NPCs
local activeNPCs: { [string]: NPCEntry } = {}

-- 3. Spawn function
local function spawnNPC(name: string, position: Vector3, stateMap, initialState: string)
    local model = createModel(name, position)  -- your model creation logic
    model:PivotTo(CFrame.new(position))
    model.Parent = Workspace

    local pathfinder = NPCPathfinder.new(model, {
        AgentRadius = 2,
        AgentHeight = 5,
        AgentCanJump = true,
        CollisionGroup = "NPCs",
    })

    local entry: NPCEntry = {
        model = model,
        pathfinder = pathfinder,
        stateMachine = nil :: any,
        behaviorType = name,
    }

    entry.stateMachine = NPCStateMachine.new(initialState, stateMap, entry)
    activeNPCs[name] = entry
end
```

**Single tick loop for ALL state machines:**

```lua
local RunService = game:GetService("RunService")

RunService.PostSimulation:Connect(function(dt)
    for _, entry in activeNPCs do
        entry.stateMachine:update(dt)
    end
end)
```

**Cleanup (call on shutdown):**

```lua
local function cleanup()
    for name, entry in activeNPCs do
        -- Destroy state machines first (onExit stops threads and pathfinder movement)
        if entry.stateMachine then
            entry.stateMachine:destroy()
        end
        -- Then destroy the pathfinder (disconnects Path.Blocked, Humanoid.Died, etc.)
        entry.pathfinder:destroy()
        -- Then destroy the model
        if entry.model then
            entry.model:Destroy()
        end
    end
    table.clear(activeNPCs)
end

-- Ensure cleanup on server shutdown
game:BindToClose(cleanup)
```

**Order matters:** Destroy state machine -> pathfinder -> model. The state machine's `destroy()` calls `onExit` on the current state, which cancels threads and stops the pathfinder cleanly. Destroying in the wrong order leaves orphaned threads.

## 7. Gotchas and Lessons (Code Generation Rules)

When generating any pathfinding code, ALWAYS apply these rules. These are derived from production debugging -- each one prevents a specific bug.

### Pathfinding

- **Waypoint index 1 is the start position.** Always start traversal from index 2. Waypoint 1 has the same XZ as the NPC but at navmesh height (Y=0), not hip height. Distance checks against it fail because of the Y mismatch. `_computePath` sets `self._currentWaypointIndex = if #self._waypoints >= 2 then 2 else 1`.
- **Skip `_computePath` during Freefall.** The NPC's position is unreliable mid-air. Return existing waypoints instead of recomputing.
- **Throttle recomputation at 50% of RecomputeInterval.** Prevents rapid recomputes from multiple code paths triggering in the same frame.
- **Path.Blocked handler: jump first, then deferred recompute.** Jumping is cheaper than recomputing and often sufficient for small obstacles. Use `task.defer` for the recompute to avoid reentrancy.
- **`followTarget` uses `MoveToFinished:Connect()` for event-driven waypoint advancement.** Never use a blocking compute-traverse-wait loop for continuous following -- it creates pauses between waypoints.
- **3-zone system in `followTarget`:** Arrival (within `arrivalDistance`, direct MoveTo) / DirectChase (within `DirectMoveDistance` + LOS, skip pathfinding) / Pathfinding (timer-based recompute, event-driven advancement).
- **`_resetMovement()` is separate from `stop()`.** `_resetMovement` clears waypoint state without cancelling the calling thread or issuing a stale MoveTo. Used inside `moveTo` to prevent self-cancellation. `stop()` cancels threads and is for external callers.
- **Never use `MoveTo(currentPosition)` as a "stop" inside movement loops.** It fires a stale `MoveToFinished(true)` that subsequent `:Wait()` calls catch instantly, causing rapid path recomputation.

### LOS Detection

- **`hasLineOfSight` MUST exclude the target model** in `FilterDescendantsInstances`. Without this, the ray hits the target player's own body parts (legs, torso) before reaching HumanoidRootPart position, making LOS always return false.
- **Use `detectNearestPlayerInRange` for initial detection.** Shared helper handles distance + optional LOS check (`REQUIRE_LOS` config). Replaces inline detection boilerplate in both Chase and Guard states.
- **Use `LOS_MEMORY` for chase maintenance, not raw LOS checks.** Raw LOS per-frame causes flicker at wall edges. `LOS_MEMORY` provides a configurable countdown (e.g., 3-5 seconds) after LOS is lost before the NPC gives up. This completes the stealth loop: walls block detection AND allow escape.
- **Always clear `ctx.losLostTimer = nil` in Chasing `onExit`.** The timer is managed by `evaluateChaseTarget` but lives on the shared context. If the state exits for any reason (target left, range exceeded), the timer must be reset so it doesn't carry over to the next chase.

### Humanoid States

- **KEEP FallingDown, GettingUp, Freefall, Landed enabled** when obstacles exist. These are the physics recovery cycle. Disabling them causes NPCs to get permanently stuck after being knocked over by collision geometry.
- **Only disable:** Climbing, Flying, Ragdoll, Seated, StrafingNoPhysics, Swimming.

### State Machine

- **States return next state name from `onUpdate` to trigger transition, `nil` to stay.** Only one transition per tick (prevents infinite loops).
- **`onEnter` fires on the initial state in the constructor.** The NPC starts doing something on frame 1, not after the first tick.
- **Context (`ctx`) is a shared mutable table.** Behavior-specific fields go here (e.g., `ctx.chaseTarget`, `ctx.wanderThread`). The state machine passes it through without inspecting it.
- **Always stop pathfinder in `onExit`.** Failure to do this leaves orphaned movement that continues after the state transition.
- **Self-transitions are allowed** (e.g., Chasing -> Chasing to switch targets). The state machine calls `onExit` then `onEnter` for self-transitions.

### Thread Safety

- **Never call `stop()` from within a thread that `stop()` will `task.cancel()`.** This kills the calling thread silently mid-execution. Use `_resetMovement()` instead for internal resets.
- **After `task.wait()`, verify model still exists:** `if not ctx.model:IsDescendantOf(game) then break end`. Models can be destroyed during the wait.
- **Store thread references, cancel in `onExit`.** Every `task.spawn()` in `onEnter` needs a corresponding `task.cancel()` in `onExit`.

### Luau

- **Use `:` not `.` for method calls.** `self.method()` silently passes the table as the first positional arg instead of `self`, causing cryptic errors.
- **Use `task.wait()`, `task.spawn()`, `task.cancel()`.** NOT deprecated `wait()`, `spawn()`.
- **Set properties before parenting Instances.** Assign `.Parent` last to avoid per-property replication events.

## 8. Audit Flow

Read the user's pathfinding code, then systematically check against `references/audit-checklist.md`.

**Output format:**
1. **Critical issues** -- Will cause bugs or major performance problems. Fix immediately.
2. **Warnings** -- Works but fragile or suboptimal. Fix when convenient.

## 9. Debug Flow

Match symptoms to `references/common-pitfalls.md`. Quick-reference symptom map:

| Symptom | First Checks |
|---------|-------------|
| NPC stuck / not moving | Network ownership (`SetNetworkOwner(nil)`), `MoveToFinished` timeout, `SpawnLocation.CanCollide` blocking path, waypoint index starting at 1 instead of 2 |
| NPC stuck after collision | Recovery states disabled (`FallingDown`, `GettingUp`, `Freefall`, `Landed`) -- re-enable them |
| NPC zig-zags | `PathfindingUseImprovedSearch` not enabled, `AgentRadius` too small for model |
| Path recomputes rapidly | `MoveTo(currentPosition)` used as stop mechanism fires stale `MoveToFinished(true)` |
| LOS always false | Target model not excluded from raycast `FilterDescendantsInstances` |
| LOS flickers | Using raw LOS for chase maintenance -- use `LOS_MEMORY` timer instead |
| NPC chases forever after losing sight | `LOS_MEMORY` not configured, or `REQUIRE_LOS` is false during chase maintenance |
| NPC jitters near waypoints | Network ownership bouncing, waypoint spacing too small |
| Path returns NoPath | Destination unreachable on navmesh, agent too large for gap, geometry not in Workspace |
| `stop()` kills calling thread | Calling `stop()` from inside a thread that `stop()` cancels -- use `_resetMovement()` instead |

Always ask the user to enable nav mesh visualization (View -> Visualization Options -> Navigation Mesh) and verify the destination is reachable on the mesh.
